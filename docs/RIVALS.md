## 2. 補給車の使い方（ここに差がある）

- **台数を探索対象にしている**: 松江は**補給車0〜2台の全ケースを簡易
  ソルバで試して選ぶ**（p20上）。福井は「考えられる全ての振り分けを
  試す」（p29下）。奈良は焼きなましで台数も探索（p17下）。
  → こちらも `choose_production_kinds` で試しています。
- **減らす方向が明示**: 豊田「巡回車:補給車=1:1なら燃料切れしないが
  **効率が悪い**。補給車を少なくして回収に動ける台数を多めに取る」
  （p29上）。和歌山は**巡回車のみ3台**の構成も候補に入れる（p24上）。
  → 厳密な上限でも同じでした（32x32・7体で 補給1台373/2台311/3台252）。
- **張り付き（併走）型**: 長岡は「**最大移動距離が最小**となる地点を
  集合場所に選び同期」し、以後同ルートを併走して常時給油、**燃料残量を
  考慮不要にする**（p22上）。小山も1:1ペアで追従（p32上）。
- **先回り待機型**: 鹿児島は巡回ルートを**共通時間軸に展開して各ステップ
  の位置と残燃料を計算**し、**補給車の待機時間が少ない合流地点**を選ぶ
  （p30上）。サレジオ（p31上）、石川（p8下）、長野（p22下）、徳山
  （p12下）も同型。
- **最適化として解く**: 沖縄は巡回候補→**分枝限定で全体組合せ**→補給
  要求を**動的計画法で実現可能性判定**し、DPの遷移を辿って補給車の行動を
  復元（p10下）。一関は経路を**セル単位・時刻単位に展開**して合流可否を
  確認（p11上）。
- **補給先の優先度**: 新居浜「**当日中に新たな系列へ到達できうる巡回車を
  優先**して給油」（p19上）。
- **定点は弱い**: 仙台(名取)は中央固定で玉28（p25上）、佐世保は点在固定で
  0点（p10上）。**こちらの `HUB_DESIGN` を切っているのと同じ結論**です。

## 4. 渋滞の扱い

- **初日は全道路が順調なのを狙う**: 都城「**初日は遠方スポットへ**、2日目
  以降は渋滞を避けて平地・山地の**裏道**」（p21上）。津山（こちら）も
  「一日目は道路を積極的に通る」（p6下）。
- **予測している**: 福井「**相手の位置から翌日の動きを予測**し、ダイクストラ
  のコストに**翌日の渋滞**を織り込む」（p29下）。旭川（p25下）。米子は
  相手の行動規則を仮定して**多数回試行し各マス各時刻の通過頻度を「危険度」
  として蓄積**、周辺と前後時刻に半分の重みで拡散（p26下）。
- **わざと使う（妨害）**: 仙台(広瀬)「**全エージェントを補給車にして
  ひたすら道路を巡回して妨害するチームが現れるかもしれない**。そのため
  道路に依存しない初期解も作る」（p5上）。
- 閾値判断: 津山「道路の**80%以上が渋滞**なら、道路と平地ではなく山地と
  平地で比較する」（p6下）。

## 5. こちらがやっていなさそうな工夫（玉数を増やす手）

**(a) 在庫を吸い切る（八戸・p6上・玉51）**
> 1つのスポットから回収できる最大量は **min(在庫, 巡回車数)**。よって
> 各スポットに**その台数分の担当を割り当て**、訪問順を最近傍法で並べる。

在庫が複数あるスポットへ**複数台を同時に差し向ける**発想です。解説集で
いちばん直接的な「玉数を増やす手」でした。

**(b) 評価式に在庫を正の項として入れる（大島商船・p23下・玉52）**
数値まで公開されています。

    店舗評価（小さいほど優先）
      = 移動step + 2×燃料消費 + 各種ペナルティ
        − **30×新ブランド** − **3×在庫数**
    内部評価点（大きいほど優先）
      = 500×ブランド数 + **100×うどん数** + 残燃料
        − 4×移動回数 − **80×在庫切れ訪問**

**在庫数を加点し、在庫切れスポットへの訪問に重いペナルティ**を置いて
います。こちらは設計（`INSERT_STOCK_WEIGHTS` / `PLANNED_STOCK_WEIGHTS`）
では在庫を見ていますが、**`GreedyPolicy` の鍵には在庫が入っていません**
（鍵は 新系列→今日未取得→予約数→歩数）。貪欲の案はしばしば最良に
なるので、ここは試す価値があります。

**(c) 補給の二重取り（宇部・p15下・玉51）**
> 全体を巡る**大きなループを1本作り、巡回車は右回り、補給車は左回り**に
> 回す。こうすることで巡回車が1周する間に**補給車の数の2倍の回数の
> 燃料補給**ができる。

**(d) 全種類を取り切ったあとを別フェーズにする（久留米・p28下）**
残りステップと燃料から到達可能なスポットを探索して割り当て直す。
富山(射水)も同型（p19下）。

**(e) 経路を1本に決めない（富山(射水)・p19下）**
> 地形によって移動時間と燃料消費が異なるため**最短時間の経路が最も燃料
> 効率の良い経路になるとは限らない**。時間重視・燃料重視と条件を変えて
> 探索し、**追加の移動時間と燃料消費が少ないものだけを残す**（パレート）。

こちらは `fuel_weight` で重みを1つ決め打ちしています。鹿児島も2種類を
生成して使い分け（p30上）。

**(f) 翌日の開始位置と残燃料を評価に入れる**
ハノイ（p34上）、一関（p11上）、和歌山（p24上）、大阪公大（p31下）。
新モンゴルは**上限の置き方まで書いています**（p33上）。
> 燃料は日をまたいで持ち越すので、**日単位の貪欲は後日に車両を取り
> 残す**。各計画に「終状態が明日まだ到達できる種類」をクレジットするが、
> **実type-day 1つ未満に上限を置いて厳密採点を覆さないようにする**。

こちらの `BRAND_COVER_BONUS`（1系列の見込みに払う玉の上限）と**同じ
考え方**で、独立にたどり着いていました。

**(g) 信頼性**: 和歌山「探索が時間切れになっても回答を残せるよう、**先に
待機だけの計画を提出し、その後に検証済みの行動計画へ更新する**」
（p24上）。→ こちらの `_submit_or_wait` と同じです。

## 6. 誰も書いていないこと

- **「同じマスで夜を越した巡回車が翌朝ただで満タンになる」**（補給は歩0の
  行動段階でも走る）に言及したチームは**1つもありません**。一関の
  「日末に補給しやすい位置で終了する候補を高評価」（p11上）が最も近い
  だけです。こちらは測りましたが、**寄り道の燃料が満タンぶんを上回って
  悪化**しました（過去15試合で順位合計163→190）。
- **「補給車は燃料を1滴も使わない」**（要項p.11）を明示的に利用すると
  書いたチームもありません。宇部の逆回りループと鹿児島の待機時間最小化が
  間接的に使っている程度です。
- ビームサーチの幅、焼きなましの温度・近傍、評価関数の係数（大島商船のみ
  例外的に数値公開）。
- 松江・福井が最終的に補給車を何台にしたか。

## 7. 次に試すべき順（この測定のあと）

厳密な上限が「**実際の朝の燃料だと玉243、こちらは240（上限の99%）**」と
言っているので、**順路をどれだけ磨いても243は越えられません**。1位の304に
届く道は「日中に配る燃料を増やす」しかなく、必要量は**1台1日20燃料**
だけです（見込み0.25杯で上限310）。配っている量（1日150〜358）は足りて
いるので、残った問題は**誰に・いつ**配るかです。

1. **在庫の重みを貪欲の鍵に入れる**（大島商船型・p23下）。設計では見て
   いるのに貪欲では見ていませんでした → `GREEDY_STOCK_WEIGHT`。
2. **配った燃料の空振りを数える**。満タンに近い車に入れた回は、補給車の
   歩をそのまま捨てています。`SUPPLY_SKIP_ROOM = 0`（寄れるだけ寄る）が
   最良という過去の実測は、**空振りを数えずに出した結論**です。
3. **逆回りのループ**（宇部型・p15下）。巡回車は右回り、補給車は左回りに
   すると、追いかけるのではなく**向かい合うので出会う回数が倍**になります。
   こちらの補給車は「追いかける」形なので、相対速度がほぼ0です。ここは
   構造から違います。
4. **経路をパレートで持つ**（富山(射水)型・p19下）。`fuel_weight` で重みを
   1つ決め打ちしているので、時間重視と燃料重視を両方持って車の状態で
   選び分ける形は作れていません。
5. **動けない車を玉で値付けする**（`IMMOBILE_BALLS`）。準決勝32x32の3日目は
   朝の燃料が [80, 22, 0, 1, 69, 74] で**2台が1歩も動けませんでした**。
   その日の玉は21〜26（ほかの日は31〜40）。
